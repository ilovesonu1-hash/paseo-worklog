# Worklog · Paseo 작업 보드

**할 일, 실제로 한 일, 다음 행동을 Paseo 안에 남기는 개인용 플러그인입니다.** 중앙 보드에 여러 PC의 기존 세션을 연결하고, 각 PC에서 에이전트가 남긴 진행 보고를 모읍니다.

현재 버전은 **`0.2.2`**, 플러그인 ID는 `worklog-board`, 배포 ZIP은 `paseo-worklog-v0.2.2.zip`입니다. 0.2.1은 0.2.0에 "지금 볼 것"·"프로젝트 흐름" 화면을 추가하고 Paseo 버전 상한을 없앤 판입니다. 0.2.2는 작업에 연결하지 않은 세션을 폴더 이름으로 자동 배치하고, 세션 상태 문구를 바꿨습니다("대기 중" → "응답 완료 · 지시 대기"). v0.2의 수집기는 **플러그인이 로드될 때 데몬에서 시작**하므로 Worklog 화면을 닫아도 동작합니다. 검증 결과와 범위는 [TESTING.md](TESTING.md)에 정리합니다. 실제 사용자 PC 3대에 설치하거나 실제 휴대전화와 연결한 실사용 검증은 아직 수행하지 않았습니다.

## 할 수 있는 일

| 화면 | 기능 |
| --- | --- |
| 지금 볼 것 (기본 화면) | 모든 프로젝트에서 내 손이 필요한 작업과 세션을 급한 순서로 표시: 권한·답변 필요 → 검토 대기 → 막힘 → 세션 오류 → 진행 멈춤(진행 중인데 3일 넘게 기록과 실행 중인 세션이 없음) → 다음 행동 없음. 작업에 연결하지 않은 세션도 권한·답변 필요나 오류이면 포함 |
| 프로젝트 흐름 | 프로젝트마다 한 줄. 지금 하는 일과 다음 행동, 실행 중·권한·답변 필요 세션 수, 단계별 작업. 작업에 연결하지 않은 세션은 폴더 이름으로 자동 배치(점선 카드): 실행 중 → 진행 중, 응답 완료 → 검토, 권한·답변 필요·오류 → 막힘. 확인할 일이 있는 프로젝트가 위에 옴 |
| 작업 보드 | `할 일 · 진행 중 · 검토 · 막힘 · 완료`, 작업 생성·편집, 프로젝트 필터, 검색, 우선순위 |
| 작업 상세 | 설명, 현재 요약, 한 일, 다음 행동, 막힌 이유, 결과 근거, 연결 세션, 메모 |
| 세션 인박스 | 중앙 서버에 저장된 여러 호스트의 세션 목록, 작업 등록·연결, 마지막 수집 시각 |
| 연결 상태 | 중앙/수집·보고 역할, 수집 대상, 수집 주기, 호스트별 상태와 보고 연결 확인 |
| 수집·보고 호스트 | 중앙 연결 시각, 보고의 전송 대기·전송 완료·보류 상태, 보류 내용 확인 |
| 활동 기록·보관함 | 작업 변경과 보고·메모 기록, 연결을 유지하는 보관·복원 |
| 내보내기 | 중앙의 작업·기록을 JSON 또는 Markdown 파일로 저장 |

작업 상태는 상세 화면의 선택 버튼으로 바꿉니다. 넓은 화면에서는 다섯 열을, 좁은 화면에서는 상태 탭을 표시합니다.

"지금 볼 것"과 "프로젝트 흐름"의 세션 신호(권한·답변 필요·오류·실행 중)는 수집이 정상인 호스트의 현재 관측만 사용합니다. 오래된 관측이나 연결이 끊긴 호스트의 세션으로는 알림을 만들지 않습니다.

**세션 상태의 뜻:** "실행 중"은 에이전트가 지금 턴을 처리하는 중이라는 뜻입니다. "응답 완료 · 지시 대기"는 답을 마치고 다음 지시를 기다린다는 뜻입니다. 프로젝트가 멈췄다는 뜻이 아닙니다. 이 상태는 Paseo가 보고하는 에이전트 상태(`running`/`idle`)를 그대로 따릅니다.

**자동 배치 규칙:** 작업 폴더의 마지막 이름을 프로젝트 이름으로 씁니다. 같은 이름(대소문자 무시)의 작업 프로젝트가 있으면 그 줄에 합칩니다. 종료된 세션, 하위 세션, 작업에 연결된 세션(보관한 작업 포함)은 제외합니다. 3일 넘게 활동이 없는 응답 완료 세션은 카드로 놓지 않고 그 프로젝트 줄에 "조용한 세션" 개수로만 표시합니다. 그래서 열려 있는 프로젝트는 오래 쉬고 있어도 줄이 생깁니다. 자동 배치는 화면 표시일 뿐이고 작업을 만들거나 저장하지 않습니다. 기록을 남기려면 카드를 눌러 "작업으로 등록"하세요(앱에서 열 수 있는 세션은 대화가 열립니다).

## 실행 환경

- **Paseo stable `0.15.4`** 기준입니다. 매니페스트 허용 범위는 상한 없는 `>=0.15.4`입니다. 0.16 이상에서도 로드를 시도하지만 검증한 버전은 0.15.4뿐입니다. 보드·작업 편집·에이전트 도구는 공식 플러그인 API만 사용합니다. 세션 수집과 여러 PC 연결은 0.15.4로 고정된 내장 SDK로 데몬에 다시 접속하므로, 데몬 프로토콜이 바뀌면 이 부분만 연결 오류로 표시될 수 있습니다. Paseo를 업데이트하기 전에는 JSON으로 내보내 두세요.
- **Paseo 데몬을 실행하는 Node.js가 24 이상**이어야 합니다. 저장소는 Node의 내장 `node:sqlite`를 사용합니다. 터미널의 Node 버전과 이미 실행 중인 데몬의 Node 버전이 다를 수 있습니다.
- 설치 명령은 Paseo와 `paseo` CLI가 설치되어 있고 해당 데몬에 접근할 수 있는 환경을 전제로 합니다.
- 배포본에는 **Paseo SDK 0.15.4를 묶은 파일**이 포함됩니다. ZIP의 일반 설치에는 별도 `npm ci`가 필요하지 않습니다. 개발 환경에서 SDK를 다시 만드는 방법은 아래에 있습니다.

Paseo 관련 기준은 [v0.15.4 릴리스](https://github.com/getpaseo/paseo/releases/tag/v0.15.4), [공식 플러그인 CLI 소스](https://github.com/getpaseo/paseo/blob/v0.15.4/packages/cli/src/commands/plugin/index.ts), [플러그인 API 문서](https://github.com/getpaseo/paseo/blob/v0.15.4/public-docs/plugins/reference.md)입니다.

## 중앙 보드와 수집·보고 호스트

작업을 보관할 PC 한 대를 **중앙 보드**로 정합니다. 나머지 PC에도 같은 플러그인을 설치하고 **수집·보고 호스트**로 설정합니다.

| 역할 | 담당하는 일 |
| --- | --- |
| 중앙 보드 | 작업의 원본 저장·편집, 자신의 세션과 선택한 원격 호스트의 세션 수집, 보고 수신·버전 확인·반영 |
| 수집·보고 호스트 | 자신의 에이전트에 중앙 작업 캐시 제공, 보고를 로컬 전송 대기열에 보관, 중앙의 수집과 수신 확인에 응답 |

중앙 데몬은 자신의 호스트와 선택된 **Paseo 네이티브 Connected Hosts**를 기본 15초 간격으로 조회합니다. 연결은 중앙에서 각 원격 PC로 가는 한 단계 구성입니다. 원격 PC가 다시 중앙을 Connected Hosts에 등록할 필요는 없습니다.

**Paseo 앱에만 추가한 호스트와 중앙 데몬의 Connected Hosts는 별개입니다.** 백그라운드 수집에는 중앙 데몬의 호스트 등록이 필요합니다. 중앙이 세션을 수집할 수 있더라도, 해당 대화를 앱에서 바로 열려면 현재 Paseo 앱에도 그 호스트가 연결되어 있어야 합니다.

Worklog는 Paseo의 기존 페어링·TCP·SSH 등 지원되는 연결을 사용합니다. 별도의 HTTP 서버나 새 수신 포트를 만들지 않습니다. 원격 플러그인 RPC에는 Paseo의 기존 **`daemon.manage` 권한**이 필요합니다. 제한된 페어링에 이 권한이 없으면 보고 연결을 수행할 수 없으므로 Paseo에서 해당 연결의 권한을 확인하세요.

## GitHub에서 설치 (권장)

공개 저장소 <https://github.com/ilovesonu1-hash/paseo-worklog>에서 바로 설치합니다. **중앙 PC와 참여할 원격 PC 각각에서** 실행합니다. 먼저 아래 "1. 플러그인 기능 확인"대로 `pluginsEnabled`가 켜져 있는지 확인하세요.

```text
paseo plugin install https://github.com/ilovesonu1-hash/paseo-worklog --id worklog-board
paseo plugin ls worklog-board
```

Windows에서 `paseo`가 PATH에 없으면 `%LOCALAPPDATA%\Programs\Paseo\resources\bin\paseo.cmd`를 사용합니다. 저장소에 빌드된 SDK가 들어 있어 `npm` 설치나 빌드 단계가 없습니다. Paseo가 저장소를 자신의 플러그인 폴더에 받아 두므로 따로 둘 소스 폴더가 필요하지 않습니다.

새 커밋이 올라오면 각 PC에서 다음 명령으로 확인하고 적용합니다.

```text
paseo plugin update worklog-board --check
paseo plugin update worklog-board
```

**이미 ZIP(로컬 폴더)으로 설치한 PC:** `paseo plugin remove worklog-board` 후 위 설치 명령을 실행합니다. 작업 데이터(`plugin-data/worklog-board`)는 `remove`로 지워지지 않으며 같은 ID로 다시 설치하면 이어서 사용합니다. 그래도 먼저 JSON으로 내보내거나 그 폴더를 복사해 두세요. 2026-11-18 Paseo 0.16.1에서 이 전환과 데이터 유지(작업·세션·활동 건수 동일)를 확인했습니다.

## ZIP에서 설치

아래 절차를 **중앙 PC와 참여할 원격 PC 각각에서** 실행합니다. ZIP 안에 `paseo-worklog/` 폴더가 있고, 그 안에 `paseo-plugin.json`이 있는 구성입니다.

설치 경로는 계속 사용할 위치로 정하세요. 로컬 디렉터리 설치는 그 소스 폴더를 참조하므로 설치 후 폴더를 옮기거나 지우지 마세요.

### 1. 플러그인 기능 확인

Paseo의 **Settings → Plugins → Enable plugins**를 확인합니다. CLI에서는 현재 값을 확인한 뒤 꺼져 있을 때 활성화할 수 있습니다.

```text
paseo daemon config get pluginsEnabled
paseo daemon config set pluginsEnabled true
```

`config set`은 설정을 저장하고 실행 중인 데몬에 적용을 시도합니다. 데몬이 꺼져 있으면 설정만 저장되므로 평소 사용하는 방식으로 데몬을 시작한 뒤 설치하세요. 동작 근거는 [공식 config CLI 소스](https://github.com/getpaseo/paseo/blob/v0.15.4/packages/cli/src/commands/daemon/config.ts)입니다.

기본 홈과 다른 Paseo 인스턴스에서는 설치·조회·설정 명령에 같은 `--home "실제 Paseo 홈 경로"`를 사용하세요. 아래 예시는 기본 인스턴스 기준입니다.

### 2-A. Windows PowerShell

```powershell
$worklogZip = Join-Path $env:USERPROFILE "Downloads\paseo-worklog-v0.2.2.zip"
$worklogInstallRoot = Join-Path $env:USERPROFILE "PaseoPlugins"
Expand-Archive -LiteralPath $worklogZip -DestinationPath $worklogInstallRoot
$worklogPlugin = Join-Path $worklogInstallRoot "paseo-worklog"
Test-Path (Join-Path $worklogPlugin "paseo-plugin.json")
paseo plugin install $worklogPlugin
paseo plugin ls worklog-board
```

`Test-Path`가 `True`인지 확인하세요. `False`이면 ZIP 내부 폴더를 확인하고 `$worklogPlugin`을 실제 매니페스트 폴더로 맞춥니다.

### 2-B. macOS / Linux

```bash
worklog_zip="$HOME/Downloads/paseo-worklog-v0.2.2.zip"
mkdir -p "$HOME/PaseoPlugins"
unzip "$worklog_zip" -d "$HOME/PaseoPlugins"
ls "$HOME/PaseoPlugins/paseo-worklog/paseo-plugin.json"
paseo plugin install "$HOME/PaseoPlugins/paseo-worklog"
paseo plugin ls worklog-board
```

위 명령은 첫 설치용입니다. 이미 v0.2.0이나 v0.2.1이 설치되어 있으면 아래 **v0.2.0·v0.2.1에서 업데이트**, v0.1이 설치되어 있으면 **v0.1에서 업데이트** 절차를 사용하세요.

### 3. Worklog 열기

정상 로드되면 다음 위치에서 엽니다.

- 사이드바의 **Worklog**
- Command Center의 **Worklog 작업 보드 열기**
- 워크스페이스의 **`/worklog`**
- 워크스페이스 패널의 **Worklog**

초기 역할은 중앙 보드입니다. 워크스페이스 패널도 그 호스트의 같은 보드를 표시하며, 작업의 프로젝트 필드로 내용을 구분합니다. 원격 PC의 역할은 다음 절차에서 바꿉니다.

로드 오류는 다음 명령으로 확인합니다.

```text
paseo plugin ls worklog-board
paseo plugin logs worklog-board
```

## PC 여러 대 연결하기

1. **중앙 PC의 Worklog → 연결 상태**에서 역할을 **중앙 보드**로 두고, 표시된 **이 호스트의 서버 ID**를 복사합니다.
2. 각 원격 PC의 Worklog → 연결 상태에서 **수집·보고 호스트**를 선택합니다. 복사한 값을 **중앙 서버 ID**에 입력하고 저장합니다.
3. **중앙 PC에서만** 원격 PC들을 Paseo의 Connected Hosts에 등록합니다. 기존 등록이 있으면 그대로 사용합니다. CLI로 등록할 때는 해당 원격 PC의 실제 Paseo 연결 문자열을 사용합니다.

```text
paseo host add '<connection>' --label 'PC2'
```

`<connection>`을 원격 PC의 실제 연결 문자열로 바꿉니다. PC가 더 있으면 각 PC의 연결 문자열과 구분할 이름으로 등록합니다. 연결 정보는 Paseo의 정상 인증·페어링 절차로 준비하세요.

4. 중앙 Worklog의 **연결 상태 → 수집할 호스트**에서 원격 PC를 선택하고 **설정 저장**을 누릅니다. 호스트 ID가 아직 확인되지 않은 항목은 선택할 수 없으며 **Paseo 호스트 연결 확인 필요**로 표시됩니다.
5. **지금 수집 요청**을 누르거나 다음 수집 주기를 기다립니다. 호스트별 **마지막 성공** 시각, 세션 수와 **보고 연결됨** 표시를 확인합니다. 수집 요청 버튼의 성공은 요청을 예약했다는 뜻이며 실제 완료는 관측 시각에서 확인합니다.

수집 대상은 표시 이름이 아니라 확인된 **canonical 서버 ID**로 저장됩니다. 연결의 표시 이름이나 주소가 바뀌어도 동일성을 확인하며, 다른 서버로 바뀐 등록을 조용히 새 대상으로 간주하지 않습니다.

각 원격 화면은 보고 상태를 보여 줍니다. 작업 생성·편집·내보내기는 중앙 호스트에서 수행합니다. 역할을 바꿀 때 기존 로컬 작업은 해당 호스트에 그대로 보존되고 다른 PC로 이동하지 않습니다. 필요하면 중앙 보드 역할로 돌아가 그 기록을 확인할 수 있습니다.

## 작업을 기록하고 세션 연결하기

1. 중앙 보드의 **새 작업**에서 제목과 프로젝트를 적습니다. 다음 행동 한 줄부터 시작해도 됩니다.
2. **세션 인박스**에서 대화를 **작업으로 등록**하거나 **기존 작업에 연결**합니다. 인박스는 중앙 서버에 저장된 목록이므로 현재 앱에 직접 연결되지 않은 호스트의 세션도 표시할 수 있습니다.
3. 작업 상세에 현재 요약, 한 일, 다음 행동, 막힌 이유와 결과 근거를 남깁니다. 추가 결정은 메모로 기록할 수 있습니다.
4. 결과를 확인하고 작업 상태를 바꿉니다. 정리한 작업은 보관했다가 복원할 수 있습니다.

한 작업에는 여러 호스트의 여러 세션을 연결할 수 있습니다. 한 세션은 한 작업에만 연결되며, 호스트 ID와 세션 ID를 함께 사용합니다. 보관한 작업도 연결을 유지합니다. 다른 작업으로 옮기려면 기존 연결을 해제하세요.

## 에이전트가 진행 보고 남기기

플러그인은 **설치된 각 호스트에서 새로 열리는 실행 세션**에 다음 도구를 추가합니다.

| 도구 | 중앙에서의 동작 | 수집·보고 호스트에서의 동작 |
| --- | --- | --- |
| `worklog_get_my_task` | 이 세션에 연결된 작업과 현재 수정 버전을 읽음 | 중앙에서 받은 연결 작업 캐시, 캐시 시각·오래됨 표시, 최근 보고 전달 상태를 읽음 |
| `worklog_report` | 연결 작업에 보고를 저장하며 수정 버전을 확인 | 보고를 로컬 대기열에 영속 저장하고 전달 상태를 반환 |

먼저 중앙 보드에서 세션을 작업에 연결하고 원격 PC로 작업 정보가 전달될 때까지 기다립니다. 이후 에이전트에 다음처럼 요청할 수 있습니다.

> 연결된 Worklog 작업을 읽고 진행해 줘. 중요한 단계가 끝나면 실제로 한 일, 확인 가능한 결과 근거, 남은 문제와 다음 행동을 Worklog에 보고해 줘. 전송 대기는 중앙에 반영되었다고 표현하지 말고, 충돌이 있으면 최신 작업을 다시 읽어 줘.

`worklog_get_my_task`는 조회 도구입니다. 원격에서는 마지막으로 받은 캐시를 읽으며, 호출 자체가 즉시 최신 중앙 작업을 가져오거나 보고를 전송하는 것은 아닙니다. 반환된 캐시 시각과 `stale` 표시를 참고해야 합니다.

이미 실행 중인 세션에는 도구가 즉시 추가되지 않을 수 있습니다. 설치 후 새 세션을 시작하거나 에이전트의 **실행 세션**을 다시 열어 도구 구성을 갱신하세요. 대화 화면만 다시 여는 것으로 적용된다고 가정하지 마세요. 과거 기록 열람용 세션에는 도구를 추가하지 않습니다.

보고는 에이전트가 `worklog_report`를 **실제로 호출해야** 남습니다. 모든 대화를 자동 요약하거나 매 턴 자동 보고하도록 강제하는 기능은 없습니다. 현재 요약·한 일·다음 행동은 해당 카드 필드를 갱신하고 활동 이력을 남깁니다. 결과 근거와 막힌 이유는 보고에서 생략하면 기존 값을 유지하며, 빈 문자열을 보내면 지웁니다.

### 원격 보고의 전달 상태

중앙 데몬이 원격 대기열을 가져와 작업의 수정 버전을 확인하고, 적용 결과를 원격에 다시 알립니다.

| 표시 | 의미 |
| --- | --- |
| 전송 대기 `queued` | 원격 PC에 안전하게 저장됨. 중앙 반영은 아직 확인되지 않음 |
| 전송 완료 `applied` | 중앙 작업에 보고가 반영되었고 원격에서 수신 확인을 받음. 작업 완료 상태와는 별개 |
| 보류 `blocked` | 수정 버전 충돌, 연결 변경 등으로 보고가 중앙에 반영되지 못함. 내용과 사유를 보존 |

원격 연결이 끊겨도 저장된 대기열은 남으며 데몬 재시작 뒤에도 이어집니다. 중앙이 보고를 반영했지만 수신 확인이 유실되면 동일 요청을 다시 확인하여 중복 반영을 피합니다. 보고를 다시 보내야 할 때는 동일 `requestId`와 동일 내용으로 결과를 확인합니다.

한 번 중앙과 연결되어 작업 캐시를 받은 수집·보고 호스트는, 연결이 끊겨도 백그라운드 연결 설정이 켜져 있으면 새 보고를 대기열에 저장할 수 있습니다. **해당 호스트의 백그라운드 연결을 끄면 새 보고 접수를 거절**합니다. 기존에 저장한 보고는 보존됩니다.

충돌 보고는 자동으로 최신 작업에 덮어쓰지 않습니다. **보류 내용 확인함**은 보고를 읽었다는 표시이며, 보고를 삭제하거나 다시 전송하거나 반영 완료로 바꾸지 않습니다. 필요한 후속 보고는 최신 작업을 읽고 새 요청으로 작성해야 합니다.

전송 대기 또는 아직 확인하지 않은 보류 보고가 남아 있으면 **역할이나 중앙 서버 ID를 바꾸는 작업**을 제한합니다. 중앙 보드의 고유 ID도 함께 확인하므로 같은 서버에서 새로 만든 다른 보드에 예전 보고를 잘못 보내지 않습니다.

### 완료 판단

작업 상태와 실행 상태는 별개입니다. 한 턴이 끝나거나 세션이 유휴·종료 상태가 되어도 작업을 자동 완료하지 않습니다. 에이전트가 `done`을 보고하면 작업은 **검토**로 이동합니다. 사용자는 내용을 확인한 뒤 직접 **완료**로 저장할 수 있습니다.

결과 근거는 사용자나 에이전트가 기록한 텍스트입니다. Worklog가 파일이나 테스트 결과의 진위를 자동 검증하는 것은 아닙니다.

## 데이터와 내보내기

소스 폴더와 별개로 각 호스트의 다음 위치에 데이터를 저장합니다.

```text
<PASEO_HOME>/plugin-data/worklog-board/
```

기본 경로는 Windows의 `%USERPROFILE%\.paseo\plugin-data\worklog-board`, macOS/Linux의 `~/.paseo/plugin-data/worklog-board`입니다.

| 파일·폴더 | 내용 |
| --- | --- |
| `worklog.sqlite` | 이 호스트의 작업 원본, 활동 기록, 세션 연결, 영속 세션 목록, 호스트 관측 상태, 중앙 보드 고유 ID |
| `worker-outbox.sqlite` | 역할과 연결 설정, 중앙 작업 캐시, 원격 보고 대기열·수신 확인·보류 기록 |
| `exports/` | 중앙 보드에서 내보낸 JSON·Markdown 파일 |

세션 메타데이터에는 제목, 호스트·세션 ID, 제공자, 작업 경로, 실행 상태와 관측 시각이 포함됩니다. 수집기는 대화 본문이나 코드 파일을 읽어 저장하지 않습니다. 에이전트가 보고한 텍스트와 결과 근거는 작업 기록에 포함됩니다.

중앙의 **내보내기**는 보관한 작업을 포함한 전체 작업, 연결·관측 정보와 활동 기록을 JSON 또는 Markdown으로 저장합니다. 화면에서 저장 경로와 내용 미리보기를 확인할 수 있습니다. 파일은 **중앙 데몬이 실행되는 PC**에 저장됩니다.

화면의 **JSON 백업**은 중앙 작업 기록의 내보내기입니다. 위성의 전송 대기열과 설정까지 포함하는 전체 복구 기능은 아니며, 현재 버전에는 JSON을 다시 가져오는 기능이 없습니다. **보관함의 복원**은 같은 데이터베이스에서 보관한 작업을 보드로 되돌립니다.

SQLite는 WAL 모드로 동작합니다. 실행 중인 `.sqlite` 파일 하나만 복사한 것을 완전한 백업으로 간주하지 마세요. 파일 단위 보관은 플러그인을 비활성화해 데이터베이스를 닫은 뒤 **데이터 디렉터리 전체**를 별도 경로에 복사하세요. 중앙과 각 위성은 각자의 데이터가 있습니다.

## v0.2.0·v0.2.1에서 업데이트

0.2.1과 0.2.2는 저장 형식을 바꾸지 않으므로 데이터 전환이 없습니다. 0.2.2부터 세션 기록에 선택 필드인 마지막 활동 시각이 추가되며, 이전에 저장된 세션은 다음 수집 때 채워집니다. 새 ZIP의 `paseo-worklog/` 내용을 **기존에 설치한 같은 소스 폴더**에 덮어쓴 뒤 `paseo plugin reload worklog-board`와 `paseo plugin ls worklog-board`를 실행합니다. 여러 PC에 설치했다면 각 PC에서 같은 절차를 반복합니다.

## v0.1에서 업데이트

v0.1의 `worklog.sqlite` 경로를 그대로 사용하며, v0.2 첫 로드에서 기존 작업·기록을 유지하는 **추가 방식의 스키마 v2 전환**을 수행합니다. `worker-outbox.sqlite`도 생성됩니다. **v0.1 코드는 전환된 v2 데이터베이스를 읽을 수 없습니다.**

1. 기존 호스트에서 `paseo plugin disable worklog-board`를 실행합니다.
2. 닫힌 상태의 `plugin-data/worklog-board` 전체와 기존 소스를 별도 위치에 보관합니다.
3. 새 ZIP의 `paseo-worklog/` 내용을 **기존에 설치한 같은 소스 폴더**에 덮어씁니다.
4. 다음 명령으로 활성화·재로드하고 상태를 확인합니다.

```text
paseo plugin enable worklog-board
paseo plugin reload worklog-board
paseo plugin ls worklog-board
paseo plugin logs worklog-board
```

업데이트 후 중앙 역할을 확인하고, 참여할 원격 PC에 v0.2를 설치한 뒤 위 연결 절차를 진행합니다. 이전처럼 앱에만 연결해 두었던 호스트는 중앙 데몬의 Connected Hosts에도 등록해야 백그라운드 수집 대상으로 선택할 수 있습니다.

이전 버전으로 돌아가야 한다면 전환된 데이터에 v0.1을 실행하지 말고, 비활성화한 상태에서 보관해 둔 이전 소스와 **전환 전 데이터**를 함께 사용해야 합니다. 로컬 설치의 소스 갱신은 파일 교체와 `reload`로 관리하며 `plugin update`가 새 ZIP을 찾아 내려받지 않습니다.

## 연결이 끊겼을 때와 현재 한도

호스트별 마지막 성공 목록과 관측 시각을 중앙에 저장합니다. 오프라인이나 조회 오류는 성공한 빈 목록으로 취급하지 않으며, 기존 관측을 유지하고 갱신 지연 또는 오류로 표시합니다. 따라서 앱을 닫았다 다시 열어도 저장된 인박스를 확인할 수 있습니다.

| 항목 | 현재 동작 |
| --- | --- |
| 수집 실행 | 중앙 플러그인이 로드되고 백그라운드 연결이 켜진 동안. 화면이 닫혀 있어도 동작 |
| 수집 주기 | 기본 15초, 설정에서 5~300초. 이전 주기 처리 시간과 연결 상태에 따라 지연 가능 |
| 원격 대상 | 선택된 canonical Connected Hosts 최대 20개와 중앙 자신 |
| 호스트별 목록 | 세션과 워크스페이스 각 200개씩 페이지 조회, 각각 최대 2,000개. 한도 도달 시 일부 표시 |
| 제외 대상 | 보관된 세션, 자식·내부 세션, 보관 상태를 확인할 수 있는 워크스페이스의 세션 |
| 전체 작업 수 | 보관한 작업을 포함해 최대 2,000개 |
| 활동 화면 | 전체 최근 100개, 작업 상세 최근 50개. 전체 기록은 내보내기에 포함 |
| 원격 보고 화면 | 전송 대기·미확인 보류 전체와 최근 100개의 처리된 보고. 전체 전달 이력은 원격 SQLite에 보존 |
| 동시 편집 | 저장 시 수정 버전 확인, 충돌 안내, 응답이 불확실한 작업 요청의 동일 요청 재확인 |
| 설정 충돌 | 편집 초안을 유지하고 명시적으로 서버의 최신 설정을 다시 읽도록 안내 |

이 버전은 한 중앙 보드와 여러 수집·보고 호스트를 연결합니다. 서로 다른 중앙 보드를 병합하거나 동등한 여러 서버에 작업 원본을 복제하는 기능은 없습니다. 에이전트 자동 생성·작업 배정·프롬프트 발송, 예약 실행과 대화 자동 요약도 포함하지 않습니다.

## 일시 중지와 설치 해제

| 목적 | 명령 |
| --- | --- |
| 플러그인 일시 중지 | `paseo plugin disable worklog-board` |
| 다시 사용 | `paseo plugin enable worklog-board` |
| 소스 변경 후 재로드 | `paseo plugin reload worklog-board` |

연결 상태 화면에서 백그라운드 연결만 끌 수도 있습니다. 같은 호스트와 같은 `PASEO_HOME`으로 다시 로드하면 저장된 작업과 보고 대기열을 이어서 사용합니다.

Paseo의 `plugin remove`는 플러그인 등록과 표준 플러그인 설정을 제거합니다. **v0.15.4에서는 Worklog가 별도로 사용하는 `plugin-data/worklog-board` 디렉터리를 삭제하지 않습니다.** 관련 근거는 [공식 제거 구현](https://github.com/getpaseo/paseo/blob/v0.15.4/packages/server/src/server/plugins/index.ts)과 [설정 경로 구성](https://github.com/getpaseo/paseo/blob/v0.15.4/packages/server/src/server/bootstrap.ts)입니다.

## 개발과 검증

프로젝트 폴더에서 Node.js 24 이상으로 실행합니다.

```text
npm ci
npm run build:sdk
```
